## 衡量什么

| 指标 | 定义 | 数据来源 | 频率 |
| --- | --- | --- | --- |
| 新确认的相关来源网站 | 基线中不存在、与 Agent/开发者任务相关、正文或有用资源中新增自愿引用；需有日期与实际链接证据 | 公开页 + 核查 JSON/人工 DOM 记录 | 每周 |
| 来源主机 / 服务商 RD | 主机统计用于去重；服务商 RD 独立记录其注册域名口径，不把 GitHub 多仓库或同域多页面当多 RD | 脚本 / 同一外链提供商导出 | 每周 / 每月 |
| 可用目标、失效目标、unknown | HTTP 2xx、明确 404/410、其他无法可靠判定分开计数 | 安全 HTTP 核查；人工状态另标来源 | 每周 |
| 非品牌搜索点击 | 按相同站点范围、国家/设备筛选比较 28 天；排除 OpenAgentSkill、open agent skill、域名及其常见拼写变体 | Search Console 只读导出 | 每周观察，28 天比较 |
| 引荐访问与有效使用 | 逐来源观察实际访问、任务搜索/查看/安装意图；安装点击不能称为安装成功 | 现有网站分析与经过验证的安装反馈 | 每周 |
| DR | 只用同一提供商、同一根域名/子域名范围对照，并记录读取日期 | 用户授权的数据源或导出 | 每月 |

“争取 5–10 个相关独立网站的自然引用”是本周期工作目标，不是保证，也不是以付费/互换链接换取的配额。重复出现的已有链接不算新增；新增链接尚未被提供商发现时，记录公开证据，等待其索引更新，不填推测 DR。

Kaino 等来源使用 `noreferrer`，来源访问可能无法通过普通 referrer 归因；不要把分析工具中的零引荐访问直接解释为没有用户。需要追踪时，可在作者自愿使用的分享链接中采用稳定 UTM，保留可读的 canonical 目标；不强制作者修改安全属性。

## 每次复盘的最小记录

```text
period_start,period_end,source_url,source_host,status,first_checked_at,last_checked_at,
new_link_observed,rel,source_page_robots,target_status,evidence_file,
referral_sessions,nonbrand_search_clicks,verified_install_successes,next_action
```

`new_link_observed` 只能由与基线的实际对照确认；`referral_sessions` 等拿不到的数值留空。确认失败、没有观察到和没有权限取得数据分别记述。

## 后续数据接入

1. 收到完整 CSV/JSON 导出后，先核实提供商、时间、根域名/子域名范围与筛选条件，保留原始文件在本地。用 `source_url` 映射来源页面，`target_url` 映射目标，运行 `scripts/audit-backlinks.mjs`。
2. 输出到新的日期文件，并传入 `--previous` 保留首次检查时间；不要覆盖本轮 JSON 中的手工浏览器证据。人工与自动结果分开保留。
3. 获得 Search Console / 分析工具只读导出后，再填搜索和使用基线。公开来源核查不需要任何登录凭据；不要把后台令牌放入 CSV、报告或仓库。
4. 对新增引用优先看是否带来相关用户、搜索曝光与实际任务使用。仅 DR 上涨而用户指标长期无变化时，重新评估内容与来源选择。

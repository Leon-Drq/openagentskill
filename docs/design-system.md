# OpenAgentSkill 网站设计规范 v1.0

状态：用于新页面和现有页面的渐进修正。更新日期：2026-10-10。

## 1. 设计基准

OpenAgentSkill 帮助人和 AI Agent 发现、比较、检查并采用 Skill。界面应把任务、来源、采用条件和下一步呈现清楚。

以现有主页、`/skills` 目录和共用导航为基准：暖白背景、墨色文字、深绿重点色、克制的衬线展示标题、细边框、轻圆角控件。内容图片保留原有色彩。新页面必须先找已有组件，不为每篇文章或活动创建另一套视觉风格。

本规范定义全站共用规则，并允许页面按任务调整密度。目录需要宽网格，文章需要适合阅读的窄栏；两者共享字体角色、色彩、控件、导航和交互状态。

实现来源：`app/globals.css`、`components/site-header.module.css`、`components/marketing-page.tsx`、`components/skills-page-client.tsx`、`components/blog/article-layout.tsx`、`components/blog/editorial.module.css`。

## 2. 色彩

| 角色 | 值 | 使用规则 |
| --- | --- | --- |
| 页面底色 | `--background` / `#F8F7F3` | 全站页面背景 |
| 主文字 | `--foreground` / `#171717` | 标题、正文、关键数据 |
| 次要文字 | `--secondary` / `#626262` | 摘要、作者、日期、辅助说明 |
| 内容表面 | `--card` / `#FFFFFF` | 卡片、表单、下拉浮层 |
| 分隔线 | `--border` / `#DDDBD4` | 1px 边框和分隔线 |
| 品牌重点 | `--brand` / `#006B4F` | 主操作、当前选中、链接重点、键盘焦点 |

补充角色沿用 `--muted`、`--destructive` 和现有下拉菜单变量。深绿只表达重点，不给整段正文染色。当前主题是浅色，不在单独页面模拟另一套深色主题。

## 3. 字体与层级

| 角色 | 字体/字重 | 尺度与行为 |
| --- | --- | --- |
| 品牌展示标题 | `font-display` / Georgia 衬线栈，400 | 主页保留既有大标题；目录保留既有 30–60px 层级 |
| 文章主标题 | 同一衬线栈，400 | 32px 手机，40px 平板，48px 桌面；行高 1.2；自然换行 |
| 文章章节标题 | 同一衬线栈，400 | 24–30px；行高 1.35 |
| 工具/卡片标题 | `font-sans`，600 | 18–20px；名称是检索信息，避免抢占主标题层级 |
| 正文 | 全站 `font-sans` 栈，400 | 16px；长文行高 1.9；用 600 强调必要短语 |
| 摘要 | `font-sans`，400 | 16–18px；行高 1.8 |
| 元信息 | `font-sans`，400 | 13–14px；容许多行，不固定高度 |
| 编号、代码 | `font-mono` / Geist Mono 栈 | 12–14px；仅用于编号、命令和路径 |

中文、日文、韩文沿用字体栈的本机回退；不得强制英文断行，也不通过添加空格排版中文。不要为单个页面加载新的展示字体。避免大面积粗黑衬线标题、正文等宽字体、整句全大写。

## 4. 宽度、间距和响应式

- 全站导航：复用 `SiteHeader`，高 64px，最大宽度 1440px。
- Skills 目录：保留 1440px 宽容器、桌面筛选栏与卡片网格。
- 营销内容：优先复用 `MarketingPageShell` / `MarketingHero`，内容最大宽度 1152px。
- 长文：复用 `ArticleLayout`，外层 1152px，正文最大宽度 768px，居中；标题、摘要、目录和正文共用一条左边线。
- 手机侧边距 16px，640px 起为 24px。内容可在 320px 视口阅读。
- 基础间距以 4px 为步进，优先使用 8 / 12 / 16 / 24 / 32 / 48 / 64px。段落间距 16–20px，主要章节间距 48px。
- 双列文章目录在 640px 以下改为单列；长标题、仓库路径、翻译后的按钮文本允许换行。
- 独立操作的触控区域至少 44px；内文链接按行高呈现并保留下划线。
- 长代码和数据表可在自身容器滚动；整页不得横向滚动，不用裁切掩盖内容溢出。

## 5. 共用组件

| 场景 | 使用方式 |
| --- | --- |
| 顶部导航 / 页脚 | `SiteHeader` / `SiteFooter`；保持顺序、品牌、活动状态和移动菜单一致 |
| 语言切换 | 只用导航中的 `LanguageSwitcher`；正文和文章推广卡不重复增加语言按钮组 |
| 主操作链接 | `MarketingButtonLink variant="primary"`；深绿、白字、8px 圆角 |
| 次操作链接 | `MarketingButtonLink variant="secondary"`；边框、浅底、清楚的 hover/focus |
| 阅读中的链接 | 有下划线，hover 加深；键盘焦点可见，不只靠颜色区分 |
| 菜单与筛选 | 复用 `LanguageSwitcher`、`NativeSelect`、现有 Radix 封装；沿用键盘和焦点逻辑 |
| 目录 / 提示面板 | 1px `--border`，12px 圆角，浅色表面；普通内容卡无需强阴影 |
| 浮层 | 沿用 `dropdown-surface` 的圆角、阴影、选中和定位规则 |
| 来源记录 | 次要字号、可读路径、固定版本链接；与正文相邻，不能用“已验证”替代实际状态 |

不要直接按全局 `h1` / `button` / `a` 标签重设样式。页面特有样式用 CSS Module 或作用域类，避免改动其他页面。新增设计变量必须先查 `app/globals.css`，同一颜色不新增近似值。

## 6. 博客模板

```text
全站导航（含唯一语言入口）
       返回博客
       内容类别
       文章标题
       摘要
       作者 · 来源核查日期
       ──────────────────
       导语
       文章目录
       章节 → 工具 → 用途 / 采用条件 / 来源
       示例工作流 / 可复制的任务描述
       方法与引用
       下一步操作
全站页脚
```

每篇文章一个 H1，章节 H2，工具条目 H3。流程中的 01–04 表示真实先后关系；不要给没有顺序的所有卡片添加装饰编号。正文、署名和引用应可在服务器返回的 HTML 中读到。

已应用：创作者工作流文章的八个语言版本、博客首页入口与历史博客模板。历史 Markdown 使用 `ArticleMarkdown` 渲染，不执行原始 HTML，正文中的一级标题降为二级标题；文章署名和所介绍 Skill 的作者分别呈现。

### 资源与开发者页面

Blog、Guides、Reports（周报、月报、年度研究）、Docs、Agent Entry、API、CLI 使用 `ResourcePageShell`，指南及用例长文使用相同外壳和自身的内容结构。已存在的七种非英文 Docs/API 页也接入外壳，未翻译的内容不添加虚构的语言链接。

- 共用面包屑、32/40/48px 常规字重展示标题、相关资源入口，以及作用域内的卡片、代码、焦点和移动端间距。
- Docs/API/CLI 的长内容通过 `ResourceContents` 链接到真实章节 ID；固定导航下方保留 88px 锚点偏移。
- 卡片标题用 sans 600；章节标题用衬线 400。代码在自己的容器横向滚动，正文和路径可以换行。
- `lib/seo/resource-pages.ts` 为资源页提供独立标题、摘要、canonical、OG/Twitter；面包屑结构化数据与可见路径一致。Docs/API 的英文入口也声明真实译文的 hreflang。
- 周报/月报必须显示生成日期、样本范围、列表上限及指标口径。不得将展示条数写成全站总数，或将累计事件称为本周/月新增量。
- 增加页面时扩展共享组件。页面数据选择、发布状态和 Skills 目录布局不由资源模板改变。

## 7. 多语言与 SEO

- URL 中的语言决定文章正文，导航切换语言应停留在同一篇文章，并保留有意义的 query/hash。
- 博客首页的文章入口随导航语言指向对应译文；只有实际存在的译文才能形成链接。
- 八种译文保留独立 URL、自指 canonical、互相对应的 hreflang 和 `x-default`、站点地图、准确的 `lang` / `inLanguage`。
- 移除可见语言按钮组不等于移除译文或 SEO 标记。搜索发现依靠正常文章链接、互相对应的语言标记及站点地图。
- 不把导航切换成中文描述为尚未翻译的历史文章也已翻译。

## 8. 交互、无障碍与状态

- 键盘能够操作导航和语言菜单；Esc 收起并回到触发按钮；焦点不可只靠细边框表示。
- 提供可见 hover、focus、disabled、loading、empty 和 error 状态；操作名称描述实际动作。
- 原生链接负责导航，按钮负责操作；不把整个包含多个操作的卡片套进链接。
- 空状态说明可采取的下一步，失败状态保留用户输入。不要用虚构数据填充占位状态。
- 动效短而克制，支持 `prefers-reduced-motion`；阅读页不增加自动播放或入场动画。

## 9. 交付检查

1. 对照主页、Skills 和当前共用组件检查色彩、字重、边框、圆角与操作层级。
2. 在 320 / 390 / 768 / 1440px 检查标题、长路径、正文、按钮、目录和页脚。
3. 实际操作桌面和移动端导航语言菜单；检查 URL、正文、选中语言、键盘焦点。
4. 检查所有已支持译文，尤其长字符串；确认无重复语言栏、裁切或横向溢出。
5. 执行项目回归测试、typecheck 和生产构建；涉及 SEO 时执行文章发布检查。
6. 部署后检查线上页面、GitHub 提交和 Vercel 生产部署对应，再报告完成。

未来新增页面时先读本规范。若确有需要引入新模式，同时更新组件和本文件，记录适用场景；不得仅在某个页面堆叠覆盖样式。

# OpenAgentSkill 自有付费 Skill 方案

日期：2026-10-11。状态：产品与实施提案；未创建收费商品，未接通支付，未修改线上页面。价格均为待验证的首发假设。

- [其视频 Skill 详情页](https://skillry.dev/skills/bs-linear-agent-style-launch-video)：展示 $4.99 单买、全库订阅入口、真实结果预览、安装提示和 ZIP 下载。页面另列外部模型/API 依赖与费用。

- 本站当前自有付费目录为 0。已有目录、案例、安装展示、身份登录和价格展示；`reviewedSkillOffers` 与外链购买按钮不等于订单、支付或下载授权系统。见 `docs/skill-pricing.md`、`docs/showcase.md`。

## 2. 商品范围与起步方式

公开的免费与第三方目录继续承担搜索发现。新增 OpenAgentSkill 自有商品系列；只有由我们制作、或已明确取得相应商业分发权的交付包才进入此系列。收录的第三方 Skill 不自动变为自有商品。

首批先做 3–5 个商品，每个解决一个明确任务，展示同一交付版本真实跑出的结果。可优先评估：

| 候选 | 明确产出 | 上架前需要的证据 |
| --- | --- | --- |
| 品牌封面与社媒配图 | 同一主题的多个尺寸图片和可修改模板 | 自有模板、真实输入输出、字体与素材来源 |
| 产品演示与发布视频 | 短视频、可编辑工程、导出说明 | 实际成片、依赖、耗时与外部费用说明 |
| 多语言内容制作 | 带来源的文章草稿、配图与平台排版 | 来源处理规则、实际质量检查、发布前人工确认 |

这些是候选方向，不是已完成、已测试或已获授权的商品。首批从已有可交付工作流中筛选；无需先承诺大而全的商品库。

## 3. 单买与订阅的权益

| 方式 | 建议权益 | 首发价格假设 |
| --- | --- | --- |
| 免费体验 | 少量完整、可运行的体验 Skill | $0 |
| 单个购买 | 所购版本长期使用；该商品 12 个月内更新；订单内明确重下载与支持范围 | 按价值测试 $4.99 / $9.99 / $19.99 |
| Pro 月付 | 有效期内获取全部自有付费 Skill、新发布内容和更新 | $9.99/月，待内容规模与购买测试验证 |
| Pro 年付 | 同等权益，按年计费 | $79/年，待验证 |

建议首期支持单买与订阅两种能力，但订阅重点推广应以有足够的有效商品、且能持续更新为前提。可将 10–15 个成熟商品作为内部发布门槛，不把数量本身当作付费价值证明。第一阶段先不承诺终身全库权益。

取消订阅：建议到当期结束停止新下载和后续更新，不删除用户已经下载的文件。单买权益独立保留。已付费用户不能在相同权益已覆盖时被再次要求付款。

Skill 的本地指令与脚本可被复制，不能靠前端按钮强制收回。用户可能订阅一个月下载全部内容后取消，定价与维护计划必须容纳这种行为。订阅的持续价值来自新内容、适配更新、案例和支持。若未来提供云端生成，另行定义额度和成本；初期不把模型/API 用量默认为订阅全包。

## 4. 详情页与购买状态

沿用 `docs/design-system.md` 的暖白、墨色、深绿、字体角色、共享导航与唯一语言入口。保留现有 Skills 列表布局。先为自有付费商品增加专用详情区，再评估是否复用于其他条目。

桌面首屏采用约 2:1 双栏：

| 左侧效果区 | 右侧购买卡 |
| --- | --- |
| 大图/视频预览，首屏显示真实产出 | 名称、作者归属、版本、一句话用途 |
| 缩略图与多个案例切换 | 交付物、适用 Agent、运行依赖与额外费用 |
| 输入与输出示例，可编辑性说明 | 单买价格、月付/年付切换与权益比较 |
| 下方继续说明操作步骤、适用边界与更新日志 | 明确标注一次性付款或自动续费，显示实际结算金额 |

购买卡桌面可随滚动固定，但不能遮盖页脚。手机改为预览在上、购买信息在下；底部操作条在查看过价格信息后出现，并留足安全区，不遮挡内容。检查 320/390/768/1440 px，控件触控区至少 44 px。

状态必须区分：

- 未登录：允许看预览与价格；开始购买时登录并保留当前商品与选择。
- 未购买：可选单买或订阅，购买动作进入明确的收银台。
- 等待支付确认：显示确认中；不能凭返回页参数直接放行下载。
- 已单买/订阅有效：主操作变为安装或下载；不重复收费。
- 订阅失效但有单买权益：对应商品仍可按单买规则访问。
- 退款、撤销或支付失败：根据对应订单与有效权益更新状态，不误删其他购买权益。

“付费安装”是支付确认后解锁安装提示、CLI 或下载。普通网页不能承诺未经用户/Agent 授权直接写入其本地环境，也不能把点击复制当作安装成功。

## 5. 实施范围

需要新增商品/版本、价格、订单、订阅、下载权益和支付事件记录。持久化金额使用最小货币单位整数；订单保存购买时的金额、币种、版本及权益快照。

支付服务商需结合收款主体和可用地区确定。客户端只提交商品/方案标识，服务端选择真实价格。签名校验的服务端支付回调负责幂等发放或撤销权益；支持重复、延迟、乱序事件与退款。不能由浏览器声明已付款。

付费包放在私有存储；下载和 CLI 请求均在服务端检查身份与权益，返回短期下载授权。发布前需要逐一检查现有公开原文、manifest、Agent API、安装接口、RSC/HTML、静态资源和缓存，防止付费包经其他入口直接获取。公开可索引页面只包含商品介绍、案例和公开元数据。

复用账号页，补充“已购 Skill”“订阅管理”“订单与账单”。公共页面缓存不能包含某个用户的订单或下载令牌。

## 6. SEO/GEO 与衡量

付费墙保护交付包；商品页、真实案例、教程、适用任务、依赖和价格说明保持公开。真实上架后才输出与可见内容一致的商品/价格结构化数据。多语言沿用实际译文、自指 canonical 与 hreflang，不制造未发布商品或虚构评价。

漏斗记录：商品浏览 → 预览播放 → 选择购买方式 → 发起结算 → 支付确认 → 下载/安装请求。只有实际收到可验证的结果时才统计安装成功；复制命令、下载 ZIP 不视为运行成功。持续查看退款原因、订阅取消原因和不同渠道转化，再调整价格与选品。

## 7. 发布顺序与验收

1. 明确首批商品的来源、交付文件、真实案例、许可、价格及更新范围。
2. 完成自有商品详情页、套餐说明和账号内购买状态；保留现有目录设计。
3. 使用支付测试环境打通单买、月付/年付、回调、重复购买保护与私有下载。
4. 验证订阅取消/到期、续费失败、退款、延迟和重复回调、无权限请求、语言与手机适配。
5. 完成真实商品运行检查及仓库要求的回归测试、类型检查、生产构建，再切换真实收费与发布。

本提案不创建真实价格、支付账户或付费商品。实际收费前必须落实首批商品与交付包、收款主体、价格/币种和购买权益；这些业务值不能从竞品或现有空状态推断。

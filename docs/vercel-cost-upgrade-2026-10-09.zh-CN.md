# Vercel 成本优化升级验收

基于 2026-10-09 获取的 GitHub `origin/main`：`1d5654e`，包含 #223 的搜索增长改进。
开发分支：`codex/reduce-public-render-cost`。本文记录部署前的代码改动与本地验收；上线状态以 GitHub `main` 和 Vercel Production 的部署记录为准。

## 已实现

| 改动 | 减少的工作 | 保留的行为 |
| --- | --- | --- |
| 默认目录缓存公开展示数据及计算结果，300 秒更新窗口，按八种语言分键 | 重复数据库读取、评分组合、卡片与结构化数据准备 | 原有服务端渲染、筛选路由、滚动与返回行为 |
| `/skills/[slug]/audit` 和 `/evals` 按首次访问生成并启用 300 秒 ISR | 缓存命中时不再运行报告页面渲染函数及支持查询 | 原始网址、正文、Agent 可读内容、原有 noindex 策略 |
| 筛选结果先取当前分页，再生成完整展示卡片 | 不再为全部候选条目生成当前页看不到的卡片 | 排名、筛选、第三方条目的插入位置、总数及分页顺序 |

目录 HTML 仍是动态响应。这一阶段减少目录计算，不消除目录函数调用，也不声称目录已有 CDN 命中。
审计、评测报告的语言及其他内容参数走动态路由，避免把中文内容或查询变体混入默认页面缓存。
默认目录仅八个展示数据缓存键；搜索、筛选和未知参数不会创建无限数量的展示数据缓存。
跟踪参数和 RSC 参数不参与该缓存键，当前请求的链接参数在缓存之外生成。

没有修改 robots、抓取许可、Agent API、登录/收藏/投票权限、审核或发布规则，也没有修改 Vercel 付费设置。

## 更新与故障行为

- 默认目录缓存绑定现有 `public-skill-directory`、`public-skill-stats` 标签，沿用发布及统计更新的失效机制。
- 主数据查询降级时不写入新的目录缓存。当前请求仍可显示标明降级的内容，后台更新失败保留已有正常缓存。
- 审计、评测页使用严格的 Skill 查询；非精选条目查询失败会抛出错误，不会保存成错误的 404。真正不存在的条目仍返回 404。
- 原有精选快照和可选支持数据的保守降级行为保留。300 秒是更新窗口，并不保证所有数据严格在五分钟内刷新；底层缓存、后台再生成和故障会影响实际新鲜度。

- `pnpm test` 全量回归通过，包含新增公开展示数据缓存、参数隔离、失效、故障恢复、分页投影和报告查询错误测试。
- `pnpm typecheck` 通过。
- `pnpm lint`：0 错误，25 条原有警告；修改文件的定向检查无警告。
- `pnpm build` 成功，审计与评测路线在构建清单中为按需静态生成；没有在构建阶段预生成全站报告。
- 本地生产服务 HTTP 验收：详情、审计、评测页均获得 `x-nextjs-cache: HIT`；英文/中文目录有完整 SSR 卡片；查询变体保持动态响应；canonical、noindex、语言跳转和内部路由 404 检查通过。
- 浏览器验收：排序、第二页、浏览器返回、搜索、中英文切换、中文分类筛选均正常；语言切换保留搜索条件。
- 本地缺少特权 Supabase 凭据，因此没有验收真实账户写入。构建中其他既有页面出现了查询超时/缺少特权凭据的降级提示，构建仍成功；本次没有修改这些账户或后台功能。

## 部署后评估与回滚

对比同一项目、仅生产环境、相近流量的 24–48 小时窗口：默认目录 CPU/请求、审计及评测缓存命中率和函数调用、整体 CPU、ISR 写入及读取费用、错误率和抓取响应。
新增缓存也有读取与写入成本，最终看总费用及每千次请求成本，不能只看某一种指标。

本次没有数据库迁移或新增环境变量。回滚代码提交并重新部署即可恢复原行为。
